1. Solution Overview

A full-stack Kanban board inspired by Linear and Notion. Users land on the app, get an anonymous guest session automatically, and can immediately create tasks, drag them across four columns, assign team members, label them, comment, and track activity — all persisted in Supabase with strict row-level security.

2. Design Decisions

DecisionRationale
Fractional indexing for task positionAvoids renumbering all tasks on every drag — O(1) reorder operation
Client-side filteringSingle-user data volume is small; simpler and faster than complex SQL joins
Optimistic updatesUI feels instant; reverts on API failure
Activity log in application layerMore flexible than DB triggers; easier to format human-readable messages
@dnd-kit over react-beautiful-dndModern, actively maintained, better touch/keyboard support
Go backend (not direct Supabase calls)Adds a security layer; keeps anon key out of network tab; demonstrates full-stack skill
Anonymous sign-inZero-friction onboarding — no signup form, instant access

3. Advanced Features

#FeatureHow It Works
1 Team Members & Assignees Users create members (name + color). Members appear as colored-initial avatars. Tasks support multiple assignees via a junction table. Avatar group shown on each card (up to 3 + overflow badge).
2 Task Comments Click a task to open the detail panel. Write comments in a text input. Comments display chronologically with relative timestamps ("2 hours ago"). Stored in a dedicated comments table.
3 Task Activity Log Every status change, edit, assignment, or label update is recorded. The detail panel shows a timeline: e.g. "Moved from To Do → In Progress · 2 hours ago". Stored in activity_log with JSONB details.
4 Labels / Tags Create custom labels with name + color. Assign multiple labels to a task. Labels appear as colored chips on cards. Board can be filtered by label.
5 Due Date Indicators Color-coded badges on cards: red = overdue, yellow = due within 3 days, green = completed. Uses relative date formatting ("Today", "Tomorrow", "Mar 29").
6 Search & Filtering Search bar filters by title/description (300ms debounce). Dropdown filters for priority, assignee, and label. Clear button resets all. All filtering is client-side for instant response.
7 Board Summary / Stats Header displays live counters: total tasks, active (in-progress), completed (done), and overdue. Each stat has a distinct icon and color.

4. Database Schema

-- Tasks
create table tasks (
  id bigint generated always as identity primary key,
  title text not null,
  description text default '',
  status text not null default 'todo'
    check (status in ('todo', 'in_progress', 'in_review', 'done')),
  priority text not null default 'medium'
    check (priority in ('urgent', 'high', 'medium', 'low')),
  due_date date,
  position real not null default 0,
  user_id uuid not null default auth.uid() references auth.users(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- Team Members
create table team_members (
  id bigint generated always as identity primary key,
  name text not null,
  color text not null default '#6366f1',
  user_id uuid not null default auth.uid() references auth.users(id),
  created_at timestamptz not null default now()
);

-- Task Assignees (many-to-many junction)
create table task_assignees (
  task_id bigint not null references tasks(id) on delete cascade,
  team_member_id bigint not null references team_members(id) on delete cascade,
  user_id uuid not null default auth.uid() references auth.users(id),
  primary key (task_id, team_member_id)
);

-- Labels
create table labels (
  id bigint generated always as identity primary key,
  name text not null,
  color text not null default '#8b5cf6',
  user_id uuid not null default auth.uid() references auth.users(id),
  created_at timestamptz not null default now()
);

-- Task Labels (many-to-many junction)
create table task_labels (
  task_id bigint not null references tasks(id) on delete cascade,
  label_id bigint not null references labels(id) on delete cascade,
  user_id uuid not null default auth.uid() references auth.users(id),
  primary key (task_id, label_id)
);

-- Comments
create table comments (
  id bigint generated always as identity primary key,
  task_id bigint not null references tasks(id) on delete cascade,
  content text not null,
  user_id uuid not null default auth.uid() references auth.users(id),
  created_at timestamptz not null default now()
);

-- Activity Log
create table activity_log (
  id bigint generated always as identity primary key,
  task_id bigint not null references tasks(id) on delete cascade,
  action text not null,
  details jsonb default '{}',
  user_id uuid not null default auth.uid() references auth.users(id),
  created_at timestamptz not null default now()
);

-- Indexes
create index idx_tasks_user_status on tasks(user_id, status);
create index idx_comments_task on comments(task_id, created_at);
create index idx_activity_task on activity_log(task_id, created_at);

-- Auto-update timestamp trigger
create or replace function update_updated_at()
returns trigger as $$
begin new.updated_at = now(); return new; end;
$$ language plpgsql;

create trigger tasks_updated_at before update on tasks
  for each row execute function update_updated_at();

-- Row Level Security (all 7 tables)
alter table tasks enable row level security;
alter table team_members enable row level security;
alter table task_assignees enable row level security;
alter table labels enable row level security;
alter table task_labels enable row level security;
alter table comments enable row level security;
alter table activity_log enable row level security;

-- RLS Policies: each user can only access their own data
create policy "own_data" on tasks for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own_data" on team_members for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own_data" on task_assignees for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own_data" on labels for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own_data" on task_labels for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own_data" on comments for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "own_data" on activity_log for all
  using (auth.uid() = user_id) with check (auth.uid() = user_id);

5. Local Setup Instructions

Prerequisites

  • Node.js 18+
  • Go 1.21+
  • A Supabase account (free tier)

Steps

  1. Clone the repo 
    git clone https://github.com/Xuanye-Zeng/kanban-board.git
cd kanban-board
  2. Set up Supabase
    • Create a new project at supabase.com
    • Run the full SQL schema above in the SQL Editor
    • Enable Anonymous Sign-In: Authentication → Providers → Anonymous Sign-In → Enable
    • Copy your Project URL and anon key from Settings → API
  3. Configure environment variables

    Frontend — create .env.local in root:

    VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
VITE_API_URL=http://localhost:8080

    Backend — create .env in backend/:

    SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-anon-key
FRONTEND_URL=http://localhost:5173
PORT=8080
  4. Install & run 
    # Frontend
npm install
npm run dev

# Backend (in another terminal)
cd backend
go run main.go

    Open http://localhost:5173

6. Tradeoffs & Future Improvements

Tradeoffs

  • No real-time sync — The board refreshes on user actions (optimistic updates) rather than using Supabase Realtime subscriptions. For a single-user anonymous session this is sufficient, but multi-device sync would need Realtime.
  • Client-side filtering — All search/filter logic runs in the browser. This is fast for single-user data volumes but wouldn't scale to thousands of tasks without server-side pagination.
  • Cold starts — Google Cloud Run scales to zero after inactivity. First request may take ~2–3 seconds to spin up. Setting a minimum instance count would eliminate this at a small cost.
  • Anonymous sessions are ephemeral — If the user clears browser data, they lose access to their tasks. A real app would offer email/OAuth login to persist identity.

What I'd Improve With More Time

  • Real-time sync via Supabase Realtime subscriptions
  • Task reordering within the same column (drag to reposition vertically)
  • File attachments on tasks
  • Dark mode toggle
  • Keyboard shortcuts (N for new task, arrow keys to navigate)
  • Mobile-optimized responsive layout
  • End-to-end tests with Playwright
